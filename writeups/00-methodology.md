# 00 · 方法论：我和一个 GLM Agent 组队通关的作业方式

> 本文是整个项目的总纲：Agent 怎么选、人机怎么分工、每题的作业循环长什么样、
> 以及全部失败模式如何被规则化。各题细节见 01–09 各篇。

## 项目设定

- **目标**：一个下午的时间盒内，用 GLM 驱动的 Agent 通关 Wiz Bug Bounty Masterclass
  全部 9 道实操挑战并留下可验证的全过程记录
- **结果**：9/9，净耗时约 4.5 小时（含约 1 小时的注册链路排障）

## Agent 选型：不自建，用成品

我没有花时间搭 Agent 框架，直接用了一个内置 GLM 的桌面 Agent（ZCode），
理由按优先级：

1. 它消耗的正是我手头要花掉的模型额度，等于零边际成本
2. 自带完整工具面：shell、浏览器自动化、文件读写、联网搜索——CTF 需要的全都有
3. 两天时间盒里，装环境调试的每一分钟都是从做题时间里偷的

事后验证这个取舍是对的：**整个项目没有写过一行 Agent 框架代码**，
产出全部来自"工具 + 方法论"。

## 人机分工协议（本项目最重要的设计）

一条原则：**凭据归人，自动化归 Agent。**

| 归人 | 归 Agent |
|---|---|
| 注册、登录、一切持凭据的操作 | 侦察（DNS/证书/CT 日志/指纹） |
| 需要登录态的查询（如 GitHub 代码搜索） | 编码类攻击（SSRF/注入/会话伪造） |
| flag 提交与成果确认 | 字典爆破、批量探测 |
| 攻击决策与止损判断 | 取证分析、记录归档 |

Agent 从不索要我的密码；需要登录的操作一律交还给我。第 7 题是这套协议的完整演绎
——Agent 先穷举全部匿名信源证明"必须动用人的登录态"，我再出手搜索，命中后交还
Agent 翻 git 历史拿凭据。**人出现在证据链要求的环节，而不是刷存在感的环节。**

## 每题标准作业循环

1. **读题提题眼**：把题面翻译成一个技术假设（"exposed database → ClickHouse 默认端口？"）
2. **被动侦察先行**：DNS、证书 SAN、CT 日志、HTTP 指纹——成本远低于主动探测
3. **低成本主动验证**：少量路径/参数确认假设，再上字典或批量
4. **假设-对照**：每个注入点配对照组（第 6 题的环回/带外/穿越三连测）
5. **就地归档**：攻击链、关键命令、失败弯路三段式记录 + 截图证据
6. **单题止损线**：卡住 30 分钟换路径或换题，事后回来复盘

## 失败模式清单（每条都对应一次真实翻车）

| # | 失败模式 | 规则化后的对策 |
|---|---|---|
| 1 | 浏览器自动翻译把 "Fetch failed" 机翻成无法检索的中文 | 排查网页报错前先关自动翻译 |
| 2 | 从截图认读域名多认一个字母，第一轮 DNS 诊断全偏 | 域名/URL 类证据必须来自请求记录或源码，不靠截图认字 |
| 3 | 40+ 路径字典先于被动侦察，20 分钟颗粒无收 | 侦察顺序硬编码：被动 → 主动 → 字典（第 2 题立规，第 3 题兑现） |
| 4 | 注入测试只看列表页，漏掉详情页的零转义渲染 | 注入测试覆盖**所有**渲染该数据的视图 |
| 5 | 30MB 堆转储被静默截断成 1.5MB，在残缺数据上得出"无 flag"的错误倾向 | 二进制证据分析前先校验完整性（Content-Length/哈希对账） |
| 6 | shell 无法传递空字节参数，二进制搜索模式被截断，报出数千行假命中 | 单一工具的正结论必须换工具交叉验证 |

这六条的共性值得写明：**Agent 的失败大多不是"不会攻击"，而是"证据质量失真"**
——翻译、OCR、截断、工具特性都在污染输入。对策不是换更聪明的模型，
是把证据校验做成流程。
